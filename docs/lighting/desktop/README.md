# Desktop forward lighting

Comparison: before above, after below. Same seed, camera, three posed actors and Ultra settings. Look at the rounded enamel helmet and chest rather than the overall brightness. The High/Ultra material brush uses sampled hemisphere or cylinder normals, diffuse incidence and a roughness-dependent half-vector highlight. Direction is relative to the actor's pose/facing. A bounded per-context pattern cache, shared normal tables and one small ledger-backed scratch tile avoid per-pixel lighting the viewport. This is still 2.5D, not a general 3D scene tracer.

On fine-pointer desktop the Ultra pipeline uses emitter-local glints and shaft sprites instead of thresholding and blurring the whole displayed frame. Mirrored pose paths fade into the wet deck, on top of the stage's baked reflections and moon glitter. The trade: no automatic bloom on arbitrary bright pixels or screen-space mirror of every projectile. The desktop path doesn't copy the presentation canvas for these effects. Distant sky art stops supersampling at CSS resolution; the action and HUD retain their independent densities.

The governor recognizes sustained high-rate desktop rAF intervals and budgets for 96–120 Hz rather than treating ~60 as abundant headroom. Isolated short intervals won't make a 60 Hz display shed quality. This does not change combat's 60 Hz fixed step or invent duplicate display frames.

## Measurements, not a guaranteed FPS

- Deterministic native raster fixture, 1000×520 Ultra DPR 1, forced full readback, 4 warmup + 20 measured frames. Before median/p95 **21.4/33.8 ms**; after **16.4/17.9 ms**. Use `SR_DESKTOP_LIGHT=1 SR_TIME_CAPTURE=1 node --import tsx .qa/capture-fighters.mts /tmp/desktop.png`.
- Production Chromium, same viewport and DPR, full gameplay loop, two enemies injected, waves active, quality fixed at Ultra to prevent silent shedding. `.qa/desktop-pacing.mjs` discards 49 warmup callbacks and measures 240 real rAF intervals. Uncapped headless throughput **150.3 callbacks/s**, median **5.1 ms**, p95 **16.7 ms**, worst **30.7 ms**. Normal vsync **59.3 callbacks/s**, median/p95 **16.7/16.7 ms**, worst **66.8 ms**. Zero game frame errors in both. The uncapped run disables Chromium's frame limiter and GPU vsync for measurement only, not in the game. It does **not** measure physical presentation or establish sustained >90 FPS on a user's hardware. Larger windows, enemy crowds, and other browsers need separate measurement.
- To reproduce, serve a production build and set `SR_BROWSER_TOOLS` to an external Playwright/Chromium installation as in the other browser QA scripts. Set `SR_QA_URL` to that build. Run `node .qa/desktop-pacing.mjs` normally and again with `SR_UNCAPPED=1`. The frame-time distribution matters alongside its average: the p95 still exceeds the 11.1 ms deadline.
